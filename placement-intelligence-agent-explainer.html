Job Helper Agent

An AI career strategist for students. One orchestrator reads the student's resume, then delegates to nine specialists that recommend companies matched to the student's real level and region, chase down referral routes, analyse the resume against a job description, draft outreach, and track applications. It is built to be honest before it is impressive — it would rather tell a student the truth than flatter them into a wasted placement season.

The architecture

The root keeps control of the whole conversation and calls each specialist as a tool (AgentTool), so results flow back into one place. Specialists pass data to each other through session state; only the root can see long-term memory.

What happens in a session

The student never sees this. They upload a resume and ask questions; the orchestrator runs only the steps the question needs.

  • 01Resume arrives
    Gemini Enterprise delivers the PDF as an attachment marker with the bytes held aside. The root calls load_artifacts to actually read it — without that it would see a filename and invent a profile.
  • 02Profile is built
    profile_agent turns the resume into structured skills, projects, experience and a target role. Nothing is stored — the resume is re-read each visit by design.
  • 03Companies, matched to the student
    company_agent judges the student's real level and region, then recommends accordingly — strong students get big firms with live openings, weaker ones get startups and honest advice, all in the student's own country.
  • 04Alumni — and the honest fallback
    alumni_agent searches public sources. When it finds no one verifiable (usually), the root hands over pre-built LinkedIn search links for the student's college and target company. It never invents a person.
  • 05Every link is verified
    Before any person or job link reaches the student, verification_agent fetches it. Dead links are dropped, not shown. This is code, not a prompt — a 404 can't be argued with.
  • 06Gap, outreach, tracking, coaching
    The resume is compared to a specific job, a personalised message is drafted for a real contact, the application is recorded, and the coach turns it all into concrete next actions.
  • 07Memory is written
    On the way out, an after-turn callback saves the conversation to Memory Bank, so the student's application history survives into their next visit.

Five things that make it trustworthy

Each of these was a bug or a risk found by testing the deployed agent, then fixed — mostly by moving a guarantee out of the prompt and into code.

Links are verified, not promised safety

The agent once named a real-sounding alum and cited a profile URL that was a 404. Telling the model "only cite real links" did not stop it.

Fix: a separate agent HTTP-fetches every link and drops the dead ones. Applies to job links too.

Only the root has memory architecture

A specialist called through AgentTool gets a fresh, empty memory service — so a lookup inside one silently returns nothing. The tracker was telling students they'd never applied.

Fix: the root reads memory and restates the facts into the request it delegates.

LinkedIn is a destination, never a source compliance

Automated access to LinkedIn is prohibited and legally tested. The agent must never fetch it — even a pasted job link.

Fix: the job fetcher blocklists LinkedIn and similar sites in code; the agent hands students their own search links instead.

Honest calibre, not flattery product

A 95%-fit-for-Google score given to an average student is a lie that costs a placement season.

Fix: company recommendations are graded to the student's real level, with a kind, specific redirect when nothing fits.

Resumes are never stored privacy

A database of thousands of student resumes is a liability with little upside — the student already has the file.

Fix: the resume is re-uploaded each session and discarded. Only application history persists.

The orchestrator is the strong model reliability

On flash, the root often ended turns blank after calling a tool. Six of eight modules failed that way.

Fix: only the root runs on gemini-2.5-pro; the nine specialists stay on cheaper flash.

Limitations — stated plainly

Some of these are fixable refinements; others are hard walls set by law and by what public data actually exists.

LimitationTypeWhat it means & the honest boundary
Automatic alumni discovery is impossible hard wall That data lives on LinkedIn, which has no people-search API and prohibits scraping. With no alumni database and no college partnerships, the agent cannot name alumni itself — it can only send the student to their own LinkedIn to look.
Referrals need the student's own effort by design The agent opens the door — the right search, the ranking, the drafted message — but the student finds the person and makes the approach. Modules 4 and 6 only work once they name a real contact.
Fit is a judgement, not a metric wrinkle Company "fit" is the model's opinion, shown as Strong / Moderate / Stretch rather than a fake-precise number. The reasoning beside it is the trustworthy part.
Coach sometimes skips its specialist wrinkle Occasionally the root answers a coaching question itself instead of delegating. The answers are good, but it bypasses the intended path. Low stakes, on the fix list.
Memory lags about a minute wrinkle Memory Bank distils facts in the background. A student opening a second session immediately won't see their new history yet; five minutes later they will.
Only tested on synthetic resumes unverified Every test used clean PDFs written for the purpose. Real resumes — two columns, scans, ATS-mangled exports — are the one input class not yet exercised. Run one real resume before students do.
~45 concurrent students quota The runtime allows 90 requests/minute by default, and the fan-out to specialists spends several per turn. A larger cohort needs a quota increase requested in advance.
The recurring lesson. Almost every fix in this project moved a guarantee out of the prompt and into code. Instructing the model "don't invent links", "always reply", "only recommend realistic companies" was not enough on its own — the reliable versions are a link-fetcher, a strong orchestrator model, and a blocklist. Prompts set intent; code sets guarantees.
One step remains before students use it. The agent is registered and enabled, but Gemini Enterprise requires it to be shared with users in the console before it appears in the chat — that step has no API. And the seven quality-and-safety findings above are refinements, not blockers: the seven data-driven modules work, and the one hard-limited module (alumni) is now safe rather than misleading.
