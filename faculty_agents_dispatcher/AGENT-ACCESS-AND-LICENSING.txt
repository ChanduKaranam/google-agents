# Agent Access and Licensing Architecture

**How students on Gemini Education Standard can use agents built by faculty on
Gemini Education Pro — and why that costs us nothing per student.**

Audience: IT administrators and project stakeholders.
Last reviewed: 2026-08-13.

---

## Executive summary

Faculty build custom agents using their **Gemini Education Pro** licences.
Students hold **Gemini Education Standard** licences. Both sit inside the same
Google Workspace organisation.

**Can a Standard-licensed student open and use a Pro-built agent? Yes.**

The reason is that these agents are not distributed as Workspace features. They
are distributed as **Google Cloud** resources, reached through
`vertexaisearch.cloud.google.com`. Access is decided by **Google Cloud IAM**,
not by a user's Workspace licence tier. A student's Standard licence neither
grants nor blocks anything here; what matters is that they sign in with a valid
organisational account.

The commercial consequence is the important one: **students do not need an
upgraded personal licence.** Their usage is billed as API consumption against
our central Google Cloud project.

---

## 1. The setup

| | |
| --- | --- |
| **Faculty** | Gemini Education Pro — build and configure agents |
| **Students** | Gemini Education Standard — open and use agents |
| **Tenant** | One Google Workspace organisation, shared by both |
| **Distribution** | A link to the agent, sent to students over WhatsApp |

---

## 2. The question

> A faculty member builds an agent with a Pro licence. We send the link to 60
> students who only have Standard licences. Will it work, or will they be told
> to upgrade?

---

## 3. The answer

**It works.** A Standard licence is not a barrier, because the licence tier is
not what is being checked.

---

## 4. Why it works

### 4.1 The link points at Google Cloud, not Workspace

The links we distribute have this shape:

```
https://vertexaisearch.cloud.google.com/home/cid/{clientId}/r/agent/{agentId}/session/-
```

The domain is the point. `vertexaisearch.cloud.google.com` is a **Google Cloud**
surface. Opening it is a request against our Cloud project, not a request for a
Workspace feature bundled into a licence tier.

This is the whole architecture in one line: **we moved the access decision out
of Workspace licensing and into Cloud IAM.**

### 4.2 Access is governed by Cloud IAM

Because the resource lives in Google Cloud, access is evaluated by **Identity
and Access Management**, which knows nothing about Gemini Education tiers. IAM
asks a different question:

> Is this a valid identity in the organisation, and does the resource's sharing
> policy admit it?

Workspace tier restrictions — Pro versus Standard — are not consulted, so they
cannot block the student.

### 4.3 The agent's sharing policy admits the whole tenant

Each agent carries a `sharingConfig.scope`. Set to **`ALL_USERS`**, it admits
every authenticated user in our organisation:

```jsonc
{
  "state": "ENABLED",
  "sharingConfig": { "scope": "ALL_USERS" }
}
```

Both fields matter. `state` must be `ENABLED`, and `scope` must be `ALL_USERS`.
An unset scope behaves as `RESTRICTED`, and an agent left at `PRIVATE` is
visible only to the person who created it.

> ⚠️ **This is a prerequisite, not a default.** See section 6.

### 4.4 What actually happens when a student clicks

1. The student opens the link on their phone.
2. Google Cloud requires a signed-in Google identity.
3. It confirms the account belongs to our organisation's tenant.
4. It evaluates the agent's sharing policy — `ALL_USERS` admits them.
5. The agent opens and the student can use it.

At no point is a Gemini Education licence tier examined.

---

## 5. Billing: why this saves money

Because students are consuming a **Google Cloud** resource rather than a
Workspace entitlement, the cost model changes:

- **No per-student licence upgrade is required.** Students do not each need a
  paid Premium subscription to use these agents.
- **Usage is billed to our central Google Cloud project**, metered as API
  consumption per message.
- **Cost scales with actual use, not with headcount.** A cohort that receives an
  agent and never opens it costs nothing. Ten heavy users cost what ten heavy
  users consume.

### Why this matters at scale

Per-seat licensing charges for *access*. Cloud API billing charges for *use*.
When a large student population uses agents occasionally, paying for use is
substantially cheaper than paying for entitlement — and it removes the
administrative burden of provisioning, tracking and reclaiming individual
licences.

## 6. Prerequisite: an agent must be shared before it is distributed

The architecture above is sound, but it rests on one condition that is worth
stating explicitly, because it is a characteristic of the platform rather than
of any particular application built on it.

### 6.1 Agents are created private by default

An agent created through the Gemini Enterprise console begins its life as
`state: PRIVATE` with no `sharingConfig`. In that state it is visible only to
the person who created it. This is Gemini Enterprise's default for every agent,
regardless of who builds it, how it is built, or how the link is later
distributed.

Until the agent's state and sharing scope are set, anyone else who opens the
link receives:

> *I'm sorry, it seems you are not allowed to perform this operation. Please
> contact an administrator.*

On mobile the same condition can present differently, as a read-only
conversation reporting that the agent is no longer available.

Both messages describe the same thing: a valid link to an agent that has not
been shared.

### 6.2 Why this is easy to miss

The sharing scope is not surfaced during agent creation. Someone building an
agent has no particular reason to know the setting exists, and the agent works
perfectly for them while they are testing it — because they are its creator.
The gap only becomes visible when somebody else opens the link, which is
typically after distribution rather than before.

For that reason, sharing state is best treated as part of an agent's release
checklist rather than as something individual creators are expected to
remember. The appendix gives a one-line check.

### 6.3 Students must belong to the organisation

Access depends on the student signing in with an organisational account. A
personal Gmail address, or an account outside the organisation, will be refused
— correctly, and by design.

## 7. Summary

| Question | Answer |
| --- | --- |
| Can Standard-licensed students use Pro-built agents? | **Yes** |
| What grants them access? | Google Cloud IAM plus the agent's `ALL_USERS` sharing scope |
| Does the Workspace licence tier matter? | **No** — it is never consulted |
| Do students need a paid upgrade? | **No** |
| Who pays? | Our central Google Cloud project, metered per message |
| Does cost scale with student numbers? | No — it scales with actual usage |
| What must be configured? | `state: ENABLED` and `sharingConfig.scope: ALL_USERS` on every agent before it is distributed |

**In one sentence:** by distributing agents as Google Cloud resources rather
than Workspace features, access is decided by organisational identity instead of
licence tier — so every student can use them, and we pay for what they actually
use rather than for the right to use it.

## Appendix — verifying an agent's access configuration

To confirm an agent is correctly shared before distributing it:

```bash
curl -s -H "Authorization: Bearer $(gcloud auth print-access-token)" \
  "https://discoveryengine.googleapis.com/v1alpha/projects/{projectNumber}/locations/global/collections/default_collection/engines/{engineId}/assistants/default_assistant/agents/{agentId}" \
  | python -c "import json,sys; a=json.load(sys.stdin); \
      print(a.get('state'), (a.get('sharingConfig') or {}).get('scope'))"
```

Expected output for a student-ready agent:

```
ENABLED ALL_USERS
```

Anything else — `PRIVATE`, `RESTRICTED`, or an empty scope — means students will
be refused access.
